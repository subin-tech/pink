# 팀 협업 규칙

## 팀과 역할

우리 팀은 5명 모두 Codex를 사용해 개발합니다. 박서준을 제외한 팀원은 개발 입문자이므로, 각자 이해하고 검증할 수 있는 크기로 작업을 나눕니다.

- 박수빈: 팀장. PM 업무와 팀 조율을 맡습니다.
- 최라엘, 김은민: 박수빈과 함께 요구사항, 일정, 문서와 제출을 관리합니다.
- 박서준: 실무 총괄. 작업 분배와 진행을 조율하고 기술 문제 해결을 지원합니다.
- 오준혁: 개발을 담당하고 기술 문제 해결을 함께 지원합니다.

역할과 관계없이 전원이 자신의 이슈, 개발, 실행 확인, PR과 리뷰에 참여합니다. 각자 맡은 변경은 Codex의 도움을 받아 이해하고 설명할 수 있어야 합니다.

## 작업과 리뷰

1. 팀 대화는 카카오톡에서 하고, 작업 내용과 결정은 GitHub 이슈와 PR에 남깁니다.
2. 작업마다 이슈와 브랜치를 만들고, main에 직접 push하지 않습니다.
3. 브랜치 이름은 `feat/`, `fix/`, `docs/`, `chore/`로 시작합니다.
4. PR 하나에는 함수 하나 또는 수정 목적 하나를 담습니다. 약 100줄을 기준으로 하되, 함께 검토할 변경이 더 크면 PR에 이유를 적습니다.
5. 커밋과 PR 제목은 `영역: 변경 내용을 설명하는 문장` 형식으로 씁니다.
6. PR 작성자 외 팀원 2명 이상의 승인을 받습니다. 한 명은 이슈 요구사항과 실행 결과를, 다른 한 명은 코드·테스트·docstring을 확인합니다. 각 리뷰어는 확인한 내용과 결과를 리뷰에 남깁니다.
7. 리뷰어는 요청을 받은 뒤 48시간 안에 검토하거나 가능한 시간을 알립니다. `blocking:` 의견이 해결되지 않으면 merge하지 않습니다.
8. 수정은 같은 브랜치와 PR에서 하고, 변경 후 리뷰어에게 재검토를 요청합니다.
9. 승인한 리뷰어 중 쓰기 권한이 있는 사람이 Squash and merge하고 작업 브랜치를 삭제합니다.

## Codex와 도움 요청

- PR에는 연결된 이슈, 변경 내용, 실행 명령과 결과를 적습니다. 구현하지 않은 함수는 미구현 상태라고 명시합니다.
- 모든 PR의 `## AI use`에 사용한 도구, 위치, 방식과 사람이 직접 수정하거나 검증한 내용을 적습니다. 사용하지 않았다면 `none`으로 씁니다.
- Codex의 검토 결과도 사람이 확인한 뒤 승인합니다.
- 같은 오류가 두 번 반복되거나 30분 동안 진전이 없으면 이슈에 오류와 시도한 방법을 적고 카카오톡으로 도움을 요청합니다.
- 비밀번호, API 키, 개인정보와 재배포 권한이 없는 자료는 저장소에 올리지 않습니다.
